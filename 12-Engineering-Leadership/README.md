# 12 — Engineering Leadership

> *The best engineers don't just write good code — they make everyone around them better.*

This section covers the non-technical skills that separate great engineers from good ones: technical decision-making, written communication, code review, mentorship, estimation, and leading teams through change — including the adoption of AI tools. These skills grow more valuable as AI takes over more routine implementation work.

Start with **Making Technical Decisions** — deciding well, and matching effort to stakes, underlies every other chapter here.

## Key Ideas

- **Technical decisions are people decisions**: The best technical choice is worthless if the team can't execute it. Match effort to reversibility and clarify who decides.
- **Writing is thinking**: A good design document forces clarity before any code is written — and a clear specification is also what makes AI assistants effective.
- **Review is teaching**: Small, fast, kind, labeled code reviews improve both code and people.
- **Leadership is a choice, not a title**: You can lead from any position on the team — mentoring and sponsoring others multiplies your impact.
- **Estimates are forecasts, not promises**: Use ranges and probabilities, calibrated with data.
- **Review is the new bottleneck** *(AI era)*: When code is cheap to produce, the team's capacity to review and verify it sets the pace.
- **Measure outcomes, not output** *(AI era)*: Lead time, change failure rate, and escaped defects tell you whether AI actually helped.
- **Protect the learning curve** *(AI era)*: Junior engineers still need the struggle that builds judgment. Mentor them to use AI as a tutor, not just a generator.

## Prerequisites

At least some professional engineering experience recommended.
